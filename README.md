# TouchBridge

외장 USB 터치 모니터(브랜드 무관)의 터치를 선택한 모니터 영역에 매핑하는 macOS 메뉴 막대 앱.

## 다운로드
**[TouchBridge.dmg 받기](https://github.com/wonsunge612/TouchBridge/releases/latest/download/TouchBridge.dmg)** (항상 최신 버전) · [모든 릴리스](https://github.com/wonsunge612/TouchBridge/releases)

macOS 13 이상, Apple Silicon과 Intel 모두 지원합니다. DMG를 열고 앱을 응용 프로그램 폴더로 옮긴 뒤 실행하고, 입력 모니터링과 손쉬운 사용 권한을 허용하세요.

### "확인할 수 없는 개발자" 경고가 뜰 때
현재 배포 빌드는 Apple 공증을 받지 않아 처음 열 때 경고가 뜹니다. 한 번만 허용하면 이후에는 바로 열립니다.

1. 응용 프로그램 폴더의 TouchBridge를 엽니다. 경고 창이 뜨면 **완료**(또는 **취소**)를 누릅니다.
2. **시스템 설정 › 개인정보 보호 및 보안**을 열고 맨 아래 보안 항목으로 내려갑니다.
3. "TouchBridge이(가) 확인된 개발자가 아니므로 차단되었습니다" 옆의 **그래도 열기**를 누르고, 암호(또는 Touch ID)로 확인합니다.
4. 다시 뜨는 창에서 **열기**를 누릅니다.

macOS 13·14에서는 Finder에서 앱을 Control-클릭(우클릭) › **열기**로도 같은 효과를 낼 수 있습니다.

## 빌드 / 실행
```sh
./build_app.sh            # → build/TouchBridge.app (ad-hoc 서명)
open build/TouchBridge.app
```
처음 실행하면 **입력 모니터링**과 **손쉬운 사용** 권한을 허용해야 합니다
(시스템 설정 › 개인정보 보호 및 보안). ad-hoc 서명은 빌드할 때마다 서명이 바뀌므로,
다시 빌드한 뒤에는 목록에서 TouchBridge를 지웠다가 다시 허용해야 할 수 있습니다.

## 커밋
```sh
./commit.sh "핀치 감도 조정"   # 빌드 확인 → 개인정보 검사 → 커밋 → GitHub push
./commit.sh                   # 메시지를 비우면 바뀐 파일 이름으로 자동 생성
./commit.sh -n "설명"          # push 없이 커밋만
```
빌드가 깨졌거나, 커밋 이메일이 GitHub noreply 주소가 아니거나, 바뀐 내용에 이메일·인증서 ID·토큰처럼 보이는 값이 있으면 커밋하지 않고 멈춥니다. 내 이메일과 인증서 ID는 스크립트에 적지 않고 실행할 때마다 이 맥에서 읽어 옵니다.

## 배포
```sh
./release.sh 1.0.0         # universal 빌드 → Developer ID 서명(강화된 런타임) → 앱 공증·staple → DMG 서명·공증·staple
./release.sh 1.0.0 --dev   # 시험용: Apple Development 인증서로 서명, 공증 생략
./release.sh 1.0.0 --publish         # 빌드 후 v1.0.0 태그를 만들고 GitHub Releases에 DMG 업로드
./release.sh 1.0.0 --dev --publish   # 시험 빌드를 초안 + 사전 릴리스로 업로드
./release.sh 1.0.0 --dev --public    # 공증 없는 빌드를 바로 정식(최신) 릴리스로 공개 → 다운로드 링크가 이 버전을 가리킴
```
`--publish`는 커밋하지 않은 변경, push 안 된 커밋, 이미 있는 태그가 있으면 빌드를 시작하기 전에 멈춥니다.
결과물은 `dist/TouchBridge-<버전>.dmg`와 `.sha256` 파일입니다. 정식 배포에는 다음 두 가지를 한 번 준비해야 합니다.
1. Apple Developer Program에 가입한 뒤 **Developer ID Application** 인증서를 만듭니다 (Xcode › Settings › Accounts › Manage Certificates).
2. 공증 자격 증명을 키체인에 저장합니다:
   `xcrun notarytool store-credentials TouchBridgeNotary --apple-id <이메일> --team-id <팀ID> --password <앱 암호>`

### 자동 업데이트 (Sparkle)
앱은 하루 한 번 `releases/latest/download/appcast.xml`을 확인하고, 새 버전이 있으면 변경 내용과 함께 설치 여부를 묻습니다. 메뉴의 **업데이트 확인…**으로 바로 확인할 수도 있습니다. `release.sh`가 DMG를 EdDSA 키로 서명해 `appcast.xml`을 만들고, `--publish`일 때 릴리스에 함께 올립니다.
- 서명 키는 로그인 키체인에 있습니다. **키를 잃어버리면 기존 사용자에게 업데이트를 보낼 수 없으므로** 반드시 백업하세요: `.build/artifacts/sparkle/Sparkle/bin/generate_keys -x ~/안전한-위치/sparkle-private-key`
- 공개 키는 `Resources/Info.plist`의 `SUPublicEDKey`입니다. `release.sh`가 키체인의 키와 일치하는지 빌드 전에 확인합니다.
- 저장소가 비공개인 동안에는 appcast를 받을 수 없어 업데이트 확인이 실패합니다. 공개한 뒤부터 동작합니다.
- 로컬 시험: `DOWNLOAD_BASE=http://127.0.0.1:8765 BUILD_NUMBER=101 ./release.sh 1.0.1 --dev`로 만든 `dist/`를 로컬 서버로 띄우고, 이전 버전 앱을 `TOUCHBRIDGE_FEED_URL=http://127.0.0.1:8765/appcast.xml TOUCHBRIDGE_UPDATE_TEST=1`로 실행하면 창 없이 확인 → 다운로드 → (종료 시) 설치까지 진행됩니다.

샌드박스에서는 장치 독점, 이벤트 주입, 손쉬운 사용 API를 쓸 수 없어 Mac App Store로는 배포할 수 없습니다. 사용자는 첫 실행 때 입력 모니터링과 손쉬운 사용 권한을 허용해야 합니다.

## 동작 방식
| 단계 | 구현 |
|---|---|
| 감지 | `IOHIDManager`에서 Usage Page 0x0D / Usage 0x04 (Touch Screen) 매칭, VID 고정 없음. 연결/해제 콜백 실시간 처리 |
| 형제 인터페이스 | 대부분의 패널은 같은 USB 장치에 절대좌표 Mouse 인터페이스도 노출함 → VID/PID/LocationID가 같고 **절대좌표 X/Y**를 가진 포인터만 함께 엶. 상대좌표 마우스와 트랙패드는 건드리지 않음 |
| 가로채기 | 각 인터페이스를 `kIOHIDOptionsTypeSeizeDevice`로 독점해 macOS가 주 모니터 기준으로 커서를 움직이지 못하게 함. 실패하면 **호환 모드**로 전환: CGEventTap이 터치 리포트와 같은 시점에 들어온 시스템 이벤트만 삼킴 |
| 멀티터치 활성화 | 연결될 때 디지타이저 Feature 리포트(Contact Count Maximum 등)를 Windows처럼 읽음. ILITEK 등 일부 패널은 이 요청을 받아야 단일 터치(마우스) 모드에서 멀티터치 모드로 바뀜 |
| 파싱 | 리포트가 올 때마다 Finger 슬롯 전체를 읽어 Contact ID별로 모든 접점을 추적(Parallel/Hybrid 모드, Contact Count 반영). 디지타이저가 조용하면 포인터 인터페이스 값을 사용 |
| 제스처 | `GestureEngine`: 탭 = 처음 닿은 위치에서 클릭(10pt 이내 흔들림 무시). 움직이면 0.25초 동안 두 번째 손가락을 기다린 뒤 드래그, 가만히 0.35초 누르면 마우스 다운. 두 손가락 함께 이동 = 트랙패드식 스크롤(phase와 관성 포함), 벌리기/오므리기 = 핀치 줌(magnify 제스처, 처음 결정된 모드로 고정). **두 손가락 제스처 중과 끝난 직후 0.3초 동안은 클릭이 생기지 않음** |
| 스크롤 출력 | 대상 모니터 주사율(`NSScreen.displayLink`)에 맞춰 프레임마다 출력, 24ms 평활화. 패널(약 135Hz)과 모니터(144Hz) 주기 차이로 생기던 끊김 제거. 손을 떼면 같은 속도로 바로 관성 시작 |
| 창 활성화 | 터치가 시작될 때 손가락 아래 창이 키 창이 아니면 그 앱을 활성화하고 창을 올림(손쉬운 사용 API). 활성화가 끝날 때까지(최대 150ms) 출력을 모아 뒀다가 보냄. macOS는 비활성 창에 핀치 이벤트를 보내지 않고 첫 클릭을 활성화에만 쓰기 때문 |
| 매핑 | 패널 0…1 → 아핀 보정 → `CGDisplayBounds(대상)`. 이벤트마다 영역을 다시 읽고, `CGDisplayRegisterReconfigurationCallback`과 `didChangeScreenParameters`로 목록을 갱신 |
| 보정 | 4점을 최소제곱 아핀으로 풀어 회전·반전·축 교환·기울어짐까지 보정. 모니터와 회전 상태(`key@rotation`)별로 저장 |

## 메뉴
- 장치 상태 (독점 / 호환 모드)
- 터치 기능 켜기/끄기 (⌘T). 끄면 장치 독점을 풀고 macOS 기본 동작으로 돌아감
- 대상 모니터 목록 (재연결 후에도 vendor-model-serial로 기억)
- 핀치 줌 감도: 낮게 / 보통(기본) / 높게 / 손가락과 1:1. 출력 배율 = 손가락 간격 비율^감도(0.35 / 0.5 / 0.75 / 1.0)
- 4포인트 터치 보정… (⌘K, ESC 취소, R 다시 시작) / 보정 초기화
- 권한이 없으면 권한 안내 항목 표시
- 업데이트 확인… (⌘U), 자동으로 업데이트 확인, 현재 버전
- 로그인 시 자동 실행 (`SMAppService`, 응용 프로그램 폴더에 설치한 뒤 켜는 것을 권장)
- 종료 (⌘Q)

## 모니터 설정 유지 (DDC/CI)
휴대용 모니터는 전원이 다시 들어올 때 밝기 같은 설정이 초기화되는 경우가 많습니다. TouchBridge는 외장 모니터의 **밝기·명암·음량**을 DDC/CI로 기억해 두고, 다음 경우에 그 값으로 되돌립니다.
- 모니터가 연결될 때 (2.5초 뒤, 모니터 부팅 대기)
- DDC 응답이 끊겼다가 돌아올 때 (연결은 유지된 채 전원만 껐다 켠 경우)

모니터 버튼(OSD)으로 바꾼 값은 4초 안에 새로 기억합니다. 처음 연결한 모니터는 아무것도 쓰지 않고 현재 값만 기억합니다. 메뉴의 **모니터 설정**에서 되돌리기를 켜고 끄거나, 슬라이더로 바로 조절할 수 있습니다.
- Apple Silicon 전용입니다. 비공개 `IOAVService` I²C를 실행 시 `dlsym`으로 찾기 때문에 Intel 맥에서는 이 기능만 꺼집니다.
- USB-C(DisplayPort)나 HDMI로 연결한 모니터에서 동작합니다. DisplayLink 방식 USB 모니터는 지원하지 않습니다.
- 실측 결과 이 모니터는 쓰기 후 약 1.1초 동안 읽기에 엉뚱한 값을 돌려주고, 0.5초보다 자주 쓰면 뒤의 쓰기를 무시합니다. 그래서 읽기는 쓰기 후 1.5초, 쓰기는 0.6초 간격을 두고, 슬라이더는 마지막 값만 보냅니다.

### 맥북과 색 맞추기 (아이폰 카메라)
메뉴 › 모니터 설정 › **맥북과 색 맞추기…**에서 연속성 카메라(아이폰)로 맥북 화면과 외장 모니터를 함께 찍어, 외장 모니터의 빨강·파랑 게인(DDC)을 맥북과 같은 흰색으로 보이게 자동 조절합니다. 맞춘 게인은 기억해 두었다가 모니터를 켤 때마다 다시 적용합니다.
- 카메라의 자동 화이트밸런스·노출은 끌 수 없지만, 두 화면이 같은 프레임에 있으면 두 화면에 똑같이 적용되어 상대 비교가 안정적입니다 (실측 흔들림 약 ±0.5%).
- 측정 영역은 각 화면의 가로 가운데 50%, 세로 20~60% 띠입니다. 가장자리는 시야각 색 변화가 크고, 아래쪽에는 책상과 키보드 반사광이 붙기 때문입니다.
- 밝기가 다르면 색 비교가 틀어지므로, 측정 중에는 카메라에서 더 밝게 보이는 쪽 회색을 낮춰 두 화면 밝기를 맞춥니다.
- 게인 한 단계의 변화가 모니터마다 다릅니다. 제우스랩은 1단계가 약 7%라서 DDC만으로는 ±3.5% 안쪽까지만 맞습니다. 그래서 게인으로 대략 맞춘 뒤 **소프트웨어 미세 보정**(감마 테이블)으로 남은 차이를 메웁니다.
  - 어두운·중간·밝은 회색(0.35 / 0.6 / 0.85) 세 단계마다 빨강·파랑 배율을 따로 맞추고 그 사이는 보간합니다. 제우스랩은 밝기에 따라 파란색이 달라서 한 단계만 맞추면 어두운 화면이 어긋납니다. 실측 결과 세 단계 모두 ±0.6% 안쪽까지 맞았습니다.
  - 초록은 건드리지 않아 밝기와 밝기 곡선이 유지됩니다. 가장 밝은 단계에서만, 1을 넘으면 잘리기 때문에 세 채널을 같이 낮춥니다.
  - 외장 모니터의 테이블에만, 원래 테이블(색상 프로파일)에 곱해서 적용합니다. 맥북 화면은 바뀌지 않습니다.
  - macOS는 앱 종료·재연결·잠자기 해제·프로파일 변경 때 테이블을 되돌리므로, TouchBridge가 그것을 감지해 다시 적용합니다. 그래서 TouchBridge가 실행 중일 때만 유지되고, 감마 테이블을 쓰는 다른 앱(f.lux 등)과는 서로 덮어쓸 수 있습니다.
- 맥북의 True Tone과 Night Shift는 조명과 시간에 따라 맥북 색을 바꾸므로, 꺼 두어야 맞춘 색이 유지됩니다.
- 카메라는 사람 눈과 색을 느끼는 방식이 달라서, 측정기 보정을 대신하지는 못합니다. 영상은 메모리에서만 쓰고 저장하거나 전송하지 않습니다.

## 진단
`~/Library/Logs/TouchBridge.log`에 권한, 장치 독점 결과, 좌표 경로(디지타이저인지 마우스 인터페이스인지), 매핑된 좌표, 클릭과 스크롤 판정이 기록됩니다.

## 한계
- 핀치 줌은 비공개 CGEvent 필드(type 29, field 110/113/132)로 만듭니다. 트랙패드 핀치를 지원하는 앱(Safari, 미리보기, 지도, 사진 등)에서 동작하며, macOS 업데이트로 바뀔 수 있습니다.
- 세 손가락 제스처와 회전은 지원하지 않습니다.
- 가만히 누른 채 시작하는 드래그는 0.35초 뒤에 시작됩니다. 두 손가락 탭 오른쪽 클릭은 기본으로 꺼져 있습니다(`Tuning.twoFingerTapRightClick`).
- 호환 모드에서는 터치하는 동안(그리고 직후 80ms) 실제 마우스 클릭도 무시되고, 마우스 클릭이 약 35ms 늦게 전달됩니다.
- 모니터를 회전한 경우, 그 회전 상태에서 한 번 보정해야 합니다.
